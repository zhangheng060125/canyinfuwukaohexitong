# 先试用，再正式上线

目前可以先使用免费的个人浏览器试用版。它使用与正式系统相同的界面、课程标准与评分构成，可以测试添加员工、上传文件、评分、跟岗、指令执行复核和汇报导出。

## 立即体验：单文件试用版

下载 `docs/trial/百花里餐饮考核系统-试用版.html`，使用普通 Chrome 或 Edge 浏览器打开。网页所需程序和原计划书已包含在这个文件中，无需注册 Render、无需付费、无需安装 Python，也不依赖外部 API 或 CDN。

GitHub 仓库中可进入该文件，点击下载原文件按钮；不要把 GitHub 的源码预览当作运行中的系统。

从右上角头像切换培训专员、餐饮经理、管理层角色。顶部「试用说明」可查看限制或重置本浏览器的全部试用数据。

## 要通过网页链接体验：开启 GitHub Pages

网页文件已准备在 `gh-pages` 分支。首次开启必须由仓库所有者在 GitHub 设置中完成，当前环境没有管理仓库 Pages 设置的权限。

1. 打开 [仓库 Pages 设置](https://github.com/zhangheng060125/canyinfuwukaohexitong/settings/pages)。
2. 在 Build and deployment 下，将 Source 设为 **Deploy from a branch**。
3. Branch 选择 **gh-pages**，目录选择 **/ (root)**，点击 **Save**。
4. 等待 GitHub 完成 Pages 构建。页面显示 **Your site is live at… / Visit site** 后，点击该页面实际给出的地址，即可试用，并发给别人体验。

公开仓库通常可免费使用 GitHub Pages；如果你的仓库或账号页面提示不支持，先使用下载版即可，不需要为了试用开通付费托管，也不要为了开启 Pages 擅自公开原本的私人仓库。

不能在部署成功前把预计地址当作可用链接。以 GitHub Pages 页面显示的实际部署状态为准。

## 试用版和正式版的区别

| 能力 | 个人浏览器试用 | 正式服务器版 |
| --- | --- | --- |
| 课程、评分界面和操作流程 | 可以体验 | 可以使用 |
| 上传照片、视频、表格 | 保存到当前浏览器 | 保存到服务器 |
| 刷新后继续使用 | 保留浏览器本地记录 | 保留服务端记录 |
| 经理、培训专员等角色 | 切换视角体验 | 真实独立账号与服务端授权 |
| 多个设备共同查看、修改 | 不共享；各自独立 | 共享正式工作区 |
| 文件内容格式检查 | 基本类型/大小检查 | 服务端格式检查 |
| 存储持久性 | 受浏览器空间与清理行为影响 | 持久化磁盘并定期备份 |

请使用虚构员工和测试文件。浏览器清理网站数据、无痕模式退出或更换设备后，可能找不到原试用记录。试用记录不会自动变成正式数据；正式上线应重新建立真实员工档案。

单文件已在浏览器中验证独立加载、零外部资源请求和刷新保留记录。当前云环境的受管 Chrome 禁止 `file://` 导航，因此文件双击模式无法在此受管浏览器直接验证；普通浏览器可尝试打开，也可启用上面的 GitHub Pages 以正常 HTTPS 网页方式试用。

## 开发验证与更新

```bash
VITE_BASE_PATH=/canyinfuwukaohexitong/ npm --prefix frontend run build:trial
npm --prefix frontend run test:trial
npm --prefix frontend run build:offline
```

`build:trial` 与 `test:trial` 验证子路径托管、文件预览、刷新持久化、整改闭环、CSV 导出及手机布局。`build:offline` 生成单文件网页。

更新试用页：确认 GitHub main 分支代码与试用测试通过后运行 `bash scripts/publish-trial.sh`，仅推送生成的示例网页到 `gh-pages` 分支，不强制推送、不发布 `data/` 或任何真实上传文件。

示例数据从新建的临时数据库生成，`scripts/export-trial-seed.py` 不读取真实工作区数据库。
