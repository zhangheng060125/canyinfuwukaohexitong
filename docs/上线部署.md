# 将系统上线为可直接使用的网站

GitHub 保存项目代码；正式网站还需要运行 Python 服务，并持久保存数据库和员工上传的附件。GitHub Pages 只能运行静态页面，无法直接承载本系统完整的评分、账号及上传功能。

## 推荐入口：Render

[打开 Render 一键部署入口](https://render.com/deploy?repo=https://github.com/zhangheng060125/canyinfuwukaohexitong)

此链接是**部署入口**，不是已经上线的网站。它会读取仓库中的 `render.yaml`。只有你登录、授权仓库并确认创建服务后，Render 才开始部署并产生费用。

1. 打开上面的入口，用自己的账号登录 Render，可以选择 GitHub 登录。
2. 授权访问 `zhangheng060125/canyinfuwukaohexitong`。如果系统要求选择分支，选择 `main`。
3. 检查部署清单：Python Web Service，Starter 方案，新加坡区域，5 GB 持久化磁盘。**这是付费配置**，以 Render 确认页显示的实际价格为准；没有确认前不会由本项目自动开通收费服务。
4. 确认后等待服务状态变为 Live。Render 会显示一个由平台实际分配的 `https://…onrender.com` 地址，这才是可以给培训专员和老板使用的网站链接。无需另买域名。
5. 进入该服务的 Environment 设置，找到自动生成的 `BAIHUALI_SETUP_KEY`。在平台安全控制台查看/复制，不要粘贴到聊天、GitHub 或公开文档中。
6. 打开实际网站，点击「进入正式工作区」，填写「网站初始化密钥」、管理员姓名、账号和密码。密钥仅用于首次创建；之后使用账号密码登录。
7. 管理员在「工作区与权限 → 管理账号」中创建培训专员和餐饮经理账号。按岗位分配，使用正式工作区录入真实数据。

如果已有云服务器，可以跳过 Render。运行 README 中的安装/启动命令，通过 Nginx/Caddy 配置 HTTPS，持久保留数据目录，并在对外开放前配置 `BAIHUALI_SETUP_KEY` 与 `BAIHUALI_REQUIRE_SETUP_KEY=1`。密钥可在服务器安全环境中生成，不要写入源码。

## 部署配置已做的工作

- 一个服务同时运行前端与 API，无须分别配置 API 域名或跨域。
- 构建时安装锁定依赖，执行 TypeScript/生产构建与 API 测试。
- 使用平台 `PORT`，健康检查 `/api/health`。
- SQLite、上传目录统一放在持久磁盘 `/var/data/baihuali`。
- HTTPS Cookie，首次管理员需要初始化密钥，防止公开网站被抢先注册管理员。
- 后续推送 `main` 可触发 Render 重新部署；重部署不清空持久化数据。

## 上线后的必要验证

- 实际网址能访问工作总览，演示标记清楚；管理员能进入正式工作区。
- 两个不同账号能看到同一条真实评分，经理能复核培训专员提交的整改。
- 上传一张培训照片、一个视频、一份表格；重新登录后仍可查看/下载。
- 选择 Render 的正常服务重启，再检查同一评分和附件仍然存在。
- 老板打开日报/周期汇报，导出 CSV 或打印 PDF。

不要用没有持久磁盘的临时实例保存正式员工数据。本仓库的测试数据与运行数据未推送到 GitHub。持久化磁盘是保存数据的必要条件，但仍应定期备份数据库与附件。
