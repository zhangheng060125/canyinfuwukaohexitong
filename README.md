# 百花里 · 餐饮服务考核系统

依据用户提供的《百花里餐饮部员工培训计划书》建立的可运行 Web 应用。面向培训专员、餐饮经理与管理层，适配桌面和手机。

## 已实现

- 工作总览：团队最新均分、达标率、课程签到完成率、成绩趋势、未达标员工与待办指令。
- 培训计划：完整五门课程，排期、教学方式、参训名单、实际签到、实操照片和问题清单；缺少照片时显示留痕不完整。
- 考核评分：摆台计时 20 + 卫生抽查 20 + 服务流程演练 20 + 现场观察 30 + 口述 10，80 分合格；逐项检查、实测用时、扣分依据及附件；未达标进行二次培训。
- 员工档案：课程进度、历史评分、跟岗记录与原始证据；停用员工保留历史记录。
- 附件资料库：照片、视频、Word、PDF、Excel、CSV、TXT，多文件上传、图片/视频/PDF 预览、文件下载；单文件上限 100 MB，服务端检验常见格式内容。表格以文件留存和下载，**不自动导入或自动评分**。
- 整改闭环：管理层下达指令 → 专员开始执行 → 留痕反馈 → 提交复核 → 经理/管理层通过或退回，支持补充意见、期限、优先级与操作日志。
- 两周跟岗：达标后 14 天，每日鼓励与纠正记录；未记录日期保留为空白，不自动视为完成。
- 客诉登记：听完、复述、具体方案与时间、上报留痕；超过 50 元进入经理/管理层审批。不收集客人现场影像。
- 日报和周期汇报：日报、近 7 天、近 30 天、自定义日期；员工问题、管理摘要、考核明细，UTF-8 CSV 导出、浏览器打印/保存 PDF。
- 账号权限：独立登录账号、服务端鉴权、密码加盐哈希、12 小时会话、正式/演示数据隔离；页面每 30 秒刷新共享数据。

## 首次使用

默认打开清楚标记的**演示工作区**，四名员工、培训与成绩都是示例，没有虚构文件附件。右上角头像可以切换培训专员、餐饮经理和管理层演示视角。

使用真实数据时，点击顶部 **进入正式工作区**，填写首位管理员姓名、登录账号和至少 10 位密码。无预置正式密码。公网部署配置还要求填写托管平台自动生成的初始化密钥，防止陌生人抢先注册；只有第一次创建管理员需要。正式工作区初始为空，不导入演示员工或成绩。

管理员在 **工作区与权限 → 管理账号** 中为培训专员、餐饮经理分配独立账号。账号不是员工档案；员工需在员工档案中单独添加。通过安全渠道将各自账号交给使用人，不要在聊天、源码或日志中记录真实密码。

推荐操作顺序：

1. 添加员工，按五门课程安排非高峰培训。
2. 完成培训时勾选实际签到人员，填写当次问题清单，关联实操照片/签到表。
3. 新建考核，人工填写五个维度得分、检查项和扣分依据，关联实操证据。
4. 未达标者安排针对性复训，重新考核。达标者每天记录两周跟岗。
5. 管理层通过总览、员工档案和汇报查看问题，下达明确的整改指令，由专员反馈，管理层复核关闭。
6. 按日或按周期导出明细，在汇报页面打印或保存 PDF。查看与汇报为站内功能，未接入短信、微信、邮件推送。

## 与原计划书的对应

详见 [需求与原文对照](docs/需求与原文对照.md)。课程及完整检查点在 `backend/standards.py`，原文保留于 `docs/百花里餐饮部员工培训计划书.docx`，可从课程标准库下载。

原计划引用的《餐厅摆台 SOP》未随附，且没有给出具体摆台尺寸、计时合格阈值或逐项扣分细则。系统明确提示待补充，不编造数值；摆台用时仅记录，由考核人根据餐厅 SOP 人工评分。可在资料库选择「摆台 SOP」分类上传补充文件。

两条红线单独记录：带病上岗，以及突发事件围观/拍照/传播。标记后生成当日紧急核查指令；合格总分不替代红线核查处置。

## 安装和启动

要求 Linux、Python 3.11+、Node.js 22+、npm，使用现有独立任务检出，不需要另建 Git worktree。

在仓库根目录执行：

```bash
bash scripts/setup.sh
bash scripts/start.sh
```

安装脚本创建 `.venv`，安装 Python 锁定依赖、执行 `npm ci`、TypeScript 检查与前端构建，再运行 API 行为测试。启动脚本通过 8000 端口同时提供前端页面与 API；可用非机密变量 `PORT` 指定端口。内部健康检查：

```bash
curl --fail http://127.0.0.1:8000/api/health
```

开发时使用两个终端：

```bash
.venv/bin/python -m uvicorn backend.app:app --host 0.0.0.0 --port 8000 --reload
npm --prefix frontend run dev
```

Vite 开发服务器通过代理访问后端。修改前端后的单端口启动须重新执行 `npm --prefix frontend run build`。后端在导入时检测构建目录，第一次构建后需重启后端。

## 验证

```bash
.venv/bin/python -m unittest discover -s tests -v
npm --prefix frontend run build
npm --prefix frontend run test:e2e
```

API 测试使用临时数据库，不修改真实记录。浏览器测试使用独立 8001 端口和临时数据目录，验证上传、评分、刷新持久化、培训签到、角色切换、指令执行与验收、CSV 下载、正式工作区隔离，以及手机端所有页面。需要 Chromium，默认 `/usr/bin/chromium`，可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定现有浏览器路径。

## 数据与部署

技术：React + TypeScript + Vite；FastAPI；SQLite；服务端文件存储。无需外部数据库或第三方 API 密钥。

- 默认数据目录 `data/`：`baihuali.sqlite3` 与 `uploads/`，均被 Git 忽略。
- `BAIHUALI_DATA_DIR` 可指定持久化数据目录；保留整个目录，不能仅备份数据库而漏掉附件。
- 数据目录和 `.venv` 是可保留文件，服务进程需要每次启动。构建目录可重新生成。
- 备份或迁移时先停止本应用进程，再完整复制 `data/`（包括 SQLite WAL/SHM 文件，如存在）；恢复后重启并检查一条评分与一份附件。不要删除真实记录来重置演示。
- 本次交付为开发环境内运行的版本，**未部署至公网**。让老板和专员通过不同设备使用，需要部署到一台可访问的服务器，持久化数据目录，配置 HTTPS 与进程托管。在 HTTPS 环境设置 `COOKIE_SECURE=1`，反向代理保留原始 Host。
- 首位管理员创建入口应在对外开放前完成。演示视角仅有演示空间权限，不能访问正式数据。请勿将真实员工资料上传到公开演示空间。

本版本不包含在线编辑 Office、视频转码、自动识别评分、多门店租户管理或外部定时消息推送。MOV 等媒体能否直接播放取决于浏览器编解码器，可随时下载原文件。
